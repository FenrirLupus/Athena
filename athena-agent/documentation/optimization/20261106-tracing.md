# Tracing: one dialect, on purpose

Status: implemented 2026-11-06; phase 5 (the deferred modules, the plumbing, and the shared readers) and the final pass
(lane attribution, `core/subagents`, `providers/base`) integrated the same day — 92 of 93 runtime modules, 561 sites.
Owner: `core/trace.py`. Contract test: `tests/trace_check.py` (39 assertions, in the release gate).

Athena used to be diagnosed by reading four different ad-hoc print styles plus whatever a stack trace happened to
say. This replaces them with one module, one line format and one level switch. Everything in the turn path that wants
to say "I am doing X" calls `core.trace`; nothing there prints directly. The processes outside the turn do the same —
the resident ASR and TTS workers, `voice.py`, the voice-bank builders, the vault sweep, the updater and the curator
scripts each have their own lane — so a failed utterance, a rolled-back update and a reverted proposal are read the
same way as a failed tool call. The only things that still write to stderr directly are outside any lane and
unchanged: the offload runtime's `[offload] …` progress lines (they run before an agent exists),
`providers/local.py`'s tiering description, and one conditional line in `core/subagents.py` kept for the case where
tracing is `off` and the audit record itself failed to land.

Phase 5 instrumented the half this note deferred: the configuration and profile readers, identity, channel state,
skills, context assembly and calibration, admission and routing, the ledger view, the model store and tiering, the
vault, the provider registry, the wire and tool-call parsers, and the plumbing everything shares — durable writes,
JSON and frontmatter reads, instruction documents, secret copy, the version, and the CLI's dispatch. For those the
rule was narrower than for the turn path: a line only where a failure would need one — a write that fell back, a read
that used its default, a value that was silently substituted.


## The level model

`ATHENA_TRACE` (or `trace.configure(level=…)`) sets one integer; every call compares against it once.

| Level | Value | What you get | When to run it |
|---|---|---|---|
| `off` | 0 | Nothing printed, nothing buffered. Every call is a null object. | Default. Production. |
| `error` | 1 | Failures only: `trace.failure`, and every span that raised. | A daemon left running for days. |
| `info` | 2 | Failures + `trace.event` lines: turn start/end, model request summary, tool dispatch, channel routing. | Normal debugging, or a user reporting "it stalled". |
| `debug` | 3 | Info + one entry and one exit line per span: tool calls, provider requests, tool loading. | Reproducing a bug. This is the useful default for a bug report. |
| `trace` | 4 | Everything, including per-chunk detail. Verbose and slow. | Narrow, short: one call, not a session. |

Two rules the level model enforces:

- **A span always has an exit line.** If the body returns without calling `sp.ok()`, the context manager emits the
  exit with `status=ok` anyway. A span with an entry and no exit is indistinguishable from a hang, which is the
  failure this exists to remove.
- **A failure is recorded at `error` and above even when its span is below the level.** At `info`, a `debug` span
  prints no entry or exit, but if it raises you still get the `✗` line with its `where=`. Losing failures because
  they happened inside quiet code is the same bug as not logging them.

`off` is absolute: no console line and no buffer entry, including failures. An operator who turns tracing off gets
silence, not mostly-silence.

## The line format

One event is one line, on stderr, so stdout stays clean for the CLI and the API:

```
[trace 12:19:38.781] beta#1 → model.call provider=mock model=mock-1 messages=2 tools=14 stream=false
[trace 12:19:38.781] beta#1 ← model.call provider=mock model=mock-1 messages=2 tools=14 stream=false prompt=289 completion=51 finish=stop tool_calls=0 ms=0.0 status=ok
[trace 12:19:38.702] beta#1 · job.received author=alpha mode=chat queue=0 wait_ms=5
[trace 12:19:38.875] alpha   ✗ job.rejected author=beta mode=chat hops=4 exc=ValueError: mention chain is 4 hops deep (max 3) where=admission.py:91 in enqueue
```

- `[trace HH:MM:SS.mmm]` — local wall clock, milliseconds. Correlate against the session file, which is UTC-stamped;
  the ordering is what matters, not the offset.
- `lane[#turn]` — the channel, and the turn number when the call is inside one. This is the unit you filter by.
  The lane is either the `channel=` on the call or the lane bound around it: `core/loop.run_turn` binds once per
  turn and the channel worker once per job (`trace.lane_scope` / `@trace.lane_bound`), so a helper that can be
  called from any lane still says which one. A line emitted outside every turn carries `-`.
- glyph — `·` event, `→` span entry, `←` span exit, `✗` failure. Anything recorded at `error` level — `✗` or a
  refusal event — also carries `where=`, so the line that decided it is one grep away.
- `name` — dotted, stable, greppable: `tool.call`, `model.call`, `job.received`, `turn.end`.
- `k=v` — fields in call order, values JSON-rendered. Newlines are escaped so one event stays one line. An exit
  repeats the entry's fields and appends its outcome, so one line tells you what was attempted and how it ended.

Every field value passes through `_redact` before it is printed or stored:

- a **field name** that is a credential name (`token`, `api_key`, `password`, `authorization`, `client_secret`,
  `private_key`, …) is replaced by `[REDACTED]` wherever it appears, including inside nested dicts. Counts are not
  credential names: `tokens=1200`, `prompt_tokens=900` and `max_tokens=1024` print in full;
- a **string shaped like a credential** (`ghp_…`, `github_pat_…`, `sk-…`, `hf_…`, `xai-…`, `AKIA…`, `AIza…`,
  `Bearer …`) is masked in place — so a key pasted into an error message does not survive into the log;
- strings over 300 characters are cut with a `…(+N)` marker; `bytes` become `<N bytes>`; nesting deeper than four
  levels is elided.

This is a last line of defence, not a licence to pass secrets: instrumentation passes counts, names, statuses and
sizes, never bodies or headers.

Where a span is used, the entry carries the request's shape (tool name, model, action) and the exit carries the
outcome (status, `ms`, and counts such as bytes or tokens). The entry is what tells you it was attempted; the exit is
what tells you how it went. Both are needed, which is why the pair is enforced.

## Coverage

Measured, not remembered: `python3 scripts/trace_coverage.py` walks the runtime tree, parses each module with `ast`,
and counts it as instrumented only when it imports `core.trace` **and** has at least one real `trace.event` / `.span` /
`.failure` call site. A docstring example is not a call, so the module's own prose cannot inflate the number.

The denominator grew from 84 to 93 in phase 5: `models/`, `context/`, `data/`, `config/` and `cli/` joined the
measured tree because they were instrumented, and a table that left them out would be flattering itself.
`__init__.py` is a package marker and is excluded; `scripts/trace_coverage.py` is the measurer and excludes itself.

The 75 % floor is met with a wide margin — 92 instrumented against the 69.8 modules the target requires, 22 modules
above the line. The percentage is still a floor, not a score: "instrumented" means the module has sites where a
failure would surface, not that every branch inside it is traced. The place a failure actually lands (the turn, the
tool call, the process, the gate, the write that fell back) is traced.

### The one module left untraced, and why

`core/trace.py` is the emitter. It has no recorder call site by construction: every line it writes comes from
`_emit`, and a module that traced itself would be writing a line about writing lines, which is the recursion this
replaces. Its behaviour is asserted instead — `tests/trace_check.py`, 39 assertions, in the gate — and the coverage
script counts a module only when it has a real `trace.*` call, so this is the one honest zero.

Every other module in the measured tree is now instrumented. The earlier excuses for the twelve small modules
(`timefmt`, `paths`, `mentions`, `metrics`, `references`, `toolpacks`, `compress`, `instructions`, `updater/channels`,
`curator_diff`, `build_pages`, the `security` pack) were that they were pure, or a shim, or traced one frame down;
the final pass found that each still had a decision a reader would want told — a refused epoch, a scope that said no,
a metrics row that did not land, a proposal diff, a prompt block, a security refusal — and traced it at the point of
decision rather than leaving it to the caller. `core/subagents.py` (which printed its SQLite failure) and
`providers/base.py` (which *defined* the lane context var and never emitted) were the two real gaps.

### Documented stdout exceptions (unchanged)

- **The two `[offload] …` / tiering prints** — `providers/offload_runtime.py` prints its progress before an agent
  exists, and `providers/local.py` prints its tiering description. Both predate the trace and still run in contexts
  with no lane.
- **The audit-record failure** — `core/subagents.py` emits `✗ subagent.record.failed` when the SQLite insert that *is*
  the run record does not land, and writes one stderr line instead when tracing is `off`. A lost audit row is not a
  diagnostic, so it must not depend on a level an operator turned down for quiet; every other path in the file traces.
- **A process's one machine-readable line.** A resident worker answers on stdout: `{"listening": …}` from
  `scripts/asr_server.py` and `scripts/tts_server.py` (and, on the refusal paths, one `{"ok": false, …}` saying why it
  did not start), `{"port": …, "token": …}` from `core/credproxy.py`. A supervisor reads it; it is the process's
  product, not a diagnostic, and it goes through one `_say`-style helper per file.
  Same for the CLI surfaces: `updater/__main__.py`'s status and channel tables, `scripts/voice.py`'s single JSON
  object, `scripts/vault_sweep.py`'s report, and the diff and outcome lines `curator apply` shows a human before
  consent. Every one of those files has exactly **one** `print` site — the emitter — so a new `print` for a
  diagnostic is visible in a grep and is a uniformity failure. (`cli/__main__.py` is the CLI itself: its prints are
  the product, which is why only its dispatch is traced.)

### Known uniformity defects (found by running it, left to their owners)

- ~~Lines with no lane~~ **closed in the final pass.** A lane context var (`trace.lane_scope`, `@trace.lane_bound`) is
  bound once per turn by `core/loop.run_turn` and once per job by the channel worker, and read by every line that
  passes no `channel=`. In the same 15-suite debug run the lane-`-` share fell from 1,901 of 4,086 lines (46.5 %) to
  1,020 of 5,415 (18.8 %); `routing_check` alone went from 413/932 (44 %) to 77/1,336 (5.8 %), `admission_check` from
  722/1,608 (45 %) to 93/2,408 (3.9 %), and `instruction_docs_check` from 48/70 (69 %) to 14/70 (20 %). What remains
  is code that runs *outside* any turn — a suite calling `durable.write` or `config.load` directly, a script reading
  its own files — where `-` is the honest answer. Totals differ between runs because two of those suites are threaded.
- `core/plugins.py` forwards a plugin's stderr verbatim as `plugin.stderr line=…`. With `ATHENA_TRACE` on, the child's
  own trace line is inside that field, so it reads `line=- · plugin_runner.start …`: still one line, but not a k=v
  field a reader can parse. Skipping forwarded lines that already begin with `[trace ` would fix it at the source.
- **Two ways to record a refusal.** `trace.failure(...)` renders `✗`; 79 sites instead call
  `trace.event(..., level="error")` for a refusal or a defect — `identity.refused`, `ledger.refused`,
  `tier.refused`, `provider.register.refused`, `context.digest.refused`, `skills.refused`, `net.refused`, …, plus the
  `wire`/`tool_calls` helpers. Both carry `where=` (see below), so neither loses the frame, but a reader filtering on
  the `✗` glyph sees only the first kind. `✗` should mean "this did not happen", whichever call site wrote it.
- **Seven error-level lines report their emitter, not their decision.** `providers/wire.py` (4) and
  `providers/tool_calls.py` (3) route every line through a `_t` helper, so `where=` on their refusals reads
  `wire.py:44 in _t`. The `rule=` field still says what refused; the frame names the helper because that is the frame
  that recorded it. Passing the caller's frame through `_t` would close it.
- ~~`core/subagents.py:76` printed its SQLite failure~~ **closed in the final pass**: it is
  `✗ subagent.record.failed` with `path=`, `status=` and the frame that hit the insert.
- `✗` lines with no matching `→` (`permission.refused`, `job.rejected`, `approval.absent`, …) are correct and
  intended: a failure recorded outside a span is still a failure, and the checker treats "closed without opened" as
  legitimate while failing on "opened without closed".


**What phase 5 changed in `core/trace.py` itself.** Two integration gaps were closed in the emitter, because fixing
them at 30 call sites would have been 30 chances to forget one:

- a failure recorded without an exception (`trace.failure("permission.refused", None, …)`) now carries
  `where=<frame that decided>` instead of no frame at all — a policy refusal is the thing you most need to locate;
- an event recorded *at* error level (`trace.event(..., level="error")`) gets the same frame, so a refusal is
  actionable whichever of the two shapes its author chose.

Both are asserted in `tests/trace_check.py` (39 checks).

**What the final pass changed in `core/trace.py`.** The lane fallback above, and one inversion: the "error-level event
carries its frame" rule was written `threshold >= LEVELS["error"]`, which is true for `info`, `debug` and `trace` as
well — so `where=` was appended to *every* event, and the handful of lines that needed the frame were buried in it.
It is now `threshold <= LEVELS["error"]`: only a `·` recorded at error level carries `where=`, which is what the
format section always said and what the reader depends on.


One caveat from the first review is now closed: in `tools/loader.py` the timeout and `OSError` branches of
`tool.script` / `tool.command` used to `return` from inside the span without calling `sp.failed(...)`, so the automatic
exit line said `status=ok` beside the `· tool.script.timeout` event that said otherwise. Both branches now call
`sp.failed(exc)`, so the exit line agrees with the event.


## Reading a trail when a turn fails

1. `ATHENA_TRACE=debug` and reproduce. The lane is in every line — filter to it and the turn number.
2. Find the `✗` lines first. Each carries `exc=` (type and message, when an exception caused it), `where=`
   (`file.py:line in function` — the frame that raised, or the frame that recorded a refusal that had no exception,
   not the whole traceback) and `ms=` for how long the attempt took before it died. A refusal recorded as
   `· … level="error"` carries `where=` too, so both shapes are locatable.
3. Read *backwards* from the `✗` for the last `→` with the same name: its fields are the input shape. A tool that
   failed at 600 ms with the right inputs is a timeout; one that failed at 3 ms is a validation error.
4. If there is no `→` for the failing name at all, the code path that was supposed to instrument it never ran — look
   one level up for the last `·` event and treat the gap as the finding.
5. At the end of the turn, `turn.end` gives the totals: calls, tool rounds, usage tokens, cost and seconds. A turn
   that burned its budget without a `✗` is a loop, not an exception. (A turn closes with two `turn.end` lines on the
   same lane and turn number: the loop's — tokens, cost, model calls — then the channel's — wall time, reply size,
   outer status. They answer different questions; read the second one for what the caller saw.)

From code or a REPL, the same trail is available without the console:

```python
from core import trace
trace.configure(level="debug")        # or level="off", console=False
trace.buffer("default", limit=50)     # last 50 entries for one lane, oldest first
trace.buffer()                        # every lane merged by timestamp
trace.dump("default", "/tmp/t.json")  # write it out; returns the path actually written
```

The buffer is per lane and bounded (default 2000 entries, `ATHENA_TRACE_BUFFER` or `configure(buffer=…)`), so tracing
can be left on all day without watching memory. Oldest entries fall off the front of their own lane only.

### When the process is what died

The resident workers and the batch tools are their own processes, and each has a lane of its own: `asr`, `tts`,
`voice`, `voicebank`, `vault`, `updater`, `curator`. A request that fails inside one of them leaves three lines that
answer three different questions:

```
[trace 12:46:27.512] asr → asr.request bytes=4
[trace 12:46:27.518] asr ✗ asr.request bytes=4 ms=0.9 status=failed exc=RuntimeError: CUDA error: device-side assert triggered where=transformers.py:5 in asr
[trace 12:46:27.518] asr · asr.worker.fatal action=exit code=3 why=cuda context is unusable after a device-side assert requests=1 failures=1
```

The `✗` is the failure with its frame; `worker.fatal` is the decision that followed. A CUDA device-side assert
poisons the context, so every later request in that process would answer the same HTTP 500 — the worker exits instead,
the supervisor starts a clean one, and an operator reading the log sees one line that says *why* rather than a page of
identical errors. The same shape appears in `tts`: `✗ tts.speak`, `tts.worker.fatal`, exit 3.

For the upgrader, read the ordered `updater.step` events as the spine — `verify → backup → stop → park → swap →
health` — and the `✗ updater.apply` as the outcome, whose message names the rollback and whether the old version
answered afterwards. For the curator, `curator.refused` is the decision not to act (with `reason=`), `curator.gate` is
the verdict, and `curator.revert` is the undo — the three things that must never be inferred from a diff.


## What is deliberately not traced

- **Secrets.** Field names that name a credential are dropped; token-shaped strings are masked. No exceptions, and no
  "debug only" bypass.
- **Message bodies at `info`.** Events carry length, role, token count and status. The text of a user message, a
  model reply or a tool result is not a diagnostic; it is data, and it lives in the session file where it belongs.
  The one exception is an HTTP error detail from a provider, capped at 200 characters and printed at `debug` only,
  because "HTTP 401" alone does not say which key was refused.
- **Prompt contents.** The model call is traced by model, token counts, latency and status. What was in the context
  window is the session's job.
- **Other lanes' internals.** Each lane's buffer holds only its own lines, and every line is prefixed with its lane.
  A lane tracing itself never sees another lane's turn numbers or payloads.
- **Full tracebacks.** One frame (`where=`) is enough to locate the failure; the traceback as a whole is noise in a
  live log and is already persisted with the turn.
- **Anything at `off`.** Including failures — see above.

## Proving it

`tests/trace_check.py` is the contract, run by `tests/run_gate.sh` (39 assertions). It asserts: `off` prints and
records nothing; a debug span prints exactly one `→` and one `←`, including a body that never calls `ok()`; a raised
exception produces a `✗` line carrying the file and line that raised it; a failure recorded *without* an exception,
and an event recorded *at* error level, carry the frame that recorded them; a `api_key` field, a nested `password`, a
`sk-…` string and a `Bearer …` header never reach the console or the buffer, while `tokens=1200` survives;
`configure(buffer=5)` bounds each lane separately and drops the oldest; `dump()` writes the trail to the path it
returns.

Uniformity is checked the same way a reader would check it — one run, one regex:

```bash
ATHENA_TRACE=debug python3 tests/routing_check.py 2>/tmp/trail.err
grep -v '^\[trace ' /tmp/trail.err          # must be empty
```

Every line matches `^\[trace \d{2}:\d{2}:\d{2}\.\d{3}\] <lane>#?<turn> [·→←✗] <name>` and every `→` has at least one
`←` or `✗` on the same lane and name. A `✗` with no `→` is allowed: it is a failure recorded outside a span
(`permission.refused`, `job.rejected`). If a site grows its own `print()` or `logging.` call, that is the check that
fails.

Run across fifteen suites with `ATHENA_TRACE=debug` (routing, permissions, approvals, security, lifecycle,
tools/skills/plugins, outcomes, instruction docs, config parity, context window, ledger view, admission, memory,
system tools, curator flow) the measured result after the final pass is:

```
lines on stderr:                  5,176, of which 0 were not a trace line
names not lowercase.dotted:          0
spans opened:                    1,316, of which 0 lacked an exit
  closes:                        1,297 ←  and 19 ✗   (a failed span closes with its failure line)
failures:                           55, all with where=file:line
refusal events at error, no frame:    0   (the emitter adds the frame; there is no call site that can omit it)
credential-shaped strings:           0
lines carrying their own channel=:   0   (that would overwrite the lane mid-span)
lanes:                              18
lines with no lane (`-`):        1,066   (21 %: code running outside any turn; was 1,901 of 4,086 — 47 % — before
                                         the lane binding)
```

The line totals move between runs because `admission_check` and `routing_check` drive real channel threads; the share,
not the count, is what to compare. The interpreter was invoked through `../.venv/bin/python3`, which prints two
`RuntimeWarning`s about `sys.prefix` before any import — the environment's, not the program's — and they are excluded
above.

Two suites (`curator_flow_check`, `vault_tiering_check`) show few or zero lines when they run their subject as a
subprocess and capture its stderr; their trails were read directly instead, which is how the `curator.apply →
curator.gate → curator.applied/revert` and `vault.sweep → vault.tier` pairs were verified.
